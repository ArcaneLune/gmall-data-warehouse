# 阶段九：实时架构前置环境搭建

> 目标：完成实时数仓开发的三大前置准备——IDEA 开发环境（Maven 多模块项目）、GitLab 代码仓库、Flink + HBase 组件部署

## 第一部分：IDEA 开发环境准备

### 1.1 项目架构设计

采用 Maven 多模块结构，一个父工程 `gmall2026-realtime` 下创建四个子模块：

```
gmall2026-realtime（父工程）
├── realtime-common    — 公共模块：第三方依赖、工具类、实体类、常量类、基类
├── realtime-dim       — DIM 维度层业务代码
├── realtime-dwd       — DWD 明细层业务代码
└── realtime-dws       — DWS 汇总层业务代码
```

后三个统称业务模块，均依赖 `realtime-common`。业务模块依赖 scope 为 `provided`——`realtime-common` 打包后放到 Flink 的 `lib/` 目录下，集群已有，业务模块打包时不再重复包含。

#### ③ 解决 8080 端口冲突（Puma vs Zookeeper）

GitLab 14.0+ 默认使用 Puma 应用服务器，占用 8080 端口；Zookeeper Admin 服务也占用 8080。ZK 先启动则 GitLab Web 访问报 502。

```bash
# 修改 Puma 端口：8080 → 8089
sudo vim /var/opt/gitlab/gitlab-rails/etc/puma.rb
```

```ruby
bind 'tcp://127.0.0.1:8089'
```

```bash
sudo vim /etc/gitlab/gitlab.rb
```

```ruby
puma['port'] = 8089
```

```bash
sudo gitlab-ctl reconfigure
sudo gitlab-ctl restart
# 等待几十秒恢复 Web 访问
```

#### ④ 解决 8060 端口冲突（nginx-status vs Doris BE）

GitLab nginx-status 默认 8060 端口，Doris BE 的 `brpc_port` 也是 8060（Backend 间通信端口）。此处选择修改 GitLab 端。

```bash
sudo vim /etc/gitlab/gitlab.rb
```

```ruby
nginx['status'] = {
  "enable" => true,
  "listen_addresses" => ["127.0.0.1"],
  "fqdn" => "127.0.0.1",
  "port" => 9999,
  "vts_enable" => true,
  "options" => {
    "server_tokens" => "on",
    "access_log" => "on",
    "allow" => "127.0.0.1",
    "deny" => "all"
  }
}
```

```bash
sudo gitlab-ctl reconfigure
sudo gitlab-ctl restart
```

验证：

```bash
sudo netstat -tunlp | grep 8060   # Doris BE 占用
sudo netstat -tunlp | grep 9999   # GitLab nginx-status
```

## 第三部分：组件环境准备

### 3.1 Flink 集群部署（Standalone 模式）

#### 集群规划

| 节点 | 角色 |
|------|------|
| hadoop100 | JobManager + TaskManager |
| hadoop101 | TaskManager |
| hadoop102 | TaskManager |

#### 1）下载并解压安装包

（1）下载安装包 `flink-1.17.1-bin-scala_2.12.tgz`，将该 jar 包上传到 hadoop100 节点服务器的 `/opt/software` 路径上。

（2）在 `/opt/software` 路径上解压 `flink-1.17.1-bin-scala_2.12.tgz` 到 `/opt/module` 路径上。

```bash
[hadoop@hadoop100 software]$ tar -zxvf flink-1.17.1-bin-scala_2.12.tgz -C /opt/module/
```

#### 2）修改集群配置

（1）进入 conf 路径，修改 `flink-conf.yaml` 文件，指定 hadoop100 节点服务器为 JobManager。

```bash
[hadoop@hadoop100 conf]$ vim flink-conf.yaml
```

修改如下内容：

```yaml
# JobManager 节点地址
jobmanager.rpc.address: hadoop100
jobmanager.bind-host: 0.0.0.0
rest.address: hadoop100
rest.bind-address: 0.0.0.0
# TaskManager 节点地址，需要配置为当前机器名
taskmanager.bind-host: 0.0.0.0
taskmanager.host: hadoop100
```

（2）修改 `workers` 文件，指定 hadoop100、hadoop101 和 hadoop102 为 TaskManager。

```bash
[hadoop@hadoop100 conf]$ vim workers
```

修改如下内容：

```
hadoop100
hadoop101
hadoop102
```

（3）修改 `masters` 文件。

```bash
[hadoop@hadoop100 conf]$ vim masters
```

修改如下内容：

```
hadoop100:8081
```

（4）另外，在 `flink-conf.yaml` 文件中还可以对集群中的 JobManager 和 TaskManager 组件进行优化配置，主要配置项如下：

- `jobmanager.memory.process.size`：对 JobManager 进程可使用到的全部内存进行配置，包括 JVM 元空间和其他开销，默认为 1600M，可以根据集群规模进行适当调整。
- `taskmanager.memory.process.size`：对 TaskManager 进程可使用到的全部内存进行配置，包括 JVM 元空间和其他开销，默认为 1728M，可以根据集群规模进行适当调整。
- `taskmanager.numberOfTaskSlots`：对每个 TaskManager 能够分配的 Slot 数量进行配置，默认为 1，可根据 TaskManager 所在的机器能够提供给 Flink 的 CPU 数量决定。所谓 Slot 就是 TaskManager 中具体运行一个任务所分配的计算资源。
- `parallelism.default`：Flink 任务执行的并行度，默认为 1。优先级低于代码中进行的并行度配置和任务提交时使用参数指定的并行度数量。

#### 3）分发安装目录

（1）配置修改完毕后，将 Flink 安装目录分发给另外两个节点服务器。

```bash
[hadoop@hadoop100 module]$ xsync flink-1.17.1/
```

（2）修改 hadoop101 的 `taskmanager.host`。

```bash
[hadoop@hadoop101 conf]$ vim flink-conf.yaml
```

```bash

```


> hadoop100 同时运行 `StandaloneSessionClusterEntrypoint`（JobManager）和 `TaskManagerRunner`（TaskManager），hadoop101、hadoop102 仅运行 `TaskManagerRunner`。

#### 5）访问 Web UI

启动成功后，同样可以访问 http://hadoop100:8081 对 Flink 集群和任务进行监控管理。

> 这里可以明显看到，当前集群的 TaskManager 数量为 3；由于默认每个 TaskManager 的 Slot 数量为 1，所以总 Slot 数和可用 Slot 数都为 3。

### 3.2 HBase 集群部署

#### 集群规划

| 节点 | 角色 |
|------|------|
| hadoop100 | HMaster + RegionServer |
| hadoop101 | RegionServer |
| hadoop102 | RegionServer |

> **前置依赖**：Zookeeper 集群与 Hadoop 集群已正常部署完毕。

#### 1）解压 HBase 到指定目录

```bash
[hadoop@hadoop100 software]$ tar -zxvf hbase-2.4.11-bin.tar.gz -C /opt/module/
[hadoop@hadoop100 software]$ mv /opt/module/hbase-2.4.11 /opt/module/hbase
```

#### 2）配置环境变量

```bash
[hadoop@hadoop100 ~]$ sudo vim /etc/profile.d/my_env.sh
```

添加：

```bash
#HBASE_HOME
export HBASE_HOME=/opt/module/hbase
export PATH=$PATH:$HBASE_HOME/bin
```

使用 source 让配置的环境变量生效：

```bash
[hadoop@hadoop100 module]$ source /etc/profile.d/my_env.sh
```

#### 3）HBase 的配置文件

（1）`hbase-env.sh` 修改内容，可以添加到最后：

```bash
export HBASE_MANAGES_ZK=false
```

> 使用外部 Zookeeper 集群，不由 HBase 管理。

（2）`hbase-site.xml` 修改内容：

```xml
<?xml version="1.0"?>
<?xml-stylesheet type="text/xsl" href="configuration.xsl"?>
<configuration>
  <property>
    <name>hbase.cluster.distributed</name>
    <value>true</value>
  </property>

  <property>
    <name>hbase.zookeeper.quorum</name>
    <value>hadoop100,hadoop101,hadoop102</value>
    <description>The directory shared by RegionServers.
    </description>
  </property>

  <property>
    <name>hbase.rootdir</name>
    <value>hdfs://hadoop100:8020/hbase</value>

    </description>
  </property>

  <property>
    <name>hbase.wal.provider</name>
    <value>filesystem</value>
  </property>
</configuration>
```

（3）`regionservers`：

```
hadoop100
hadoop101
hadoop102
```

（4）解决 HBase 和 Hadoop 的 log4j 兼容性问题，修改 HBase 的 jar 包，使用 Hadoop 的 jar 包：

```bash
[hadoop@hadoop100 hbase]$ mv /opt/module/hbase/lib/client-facing-thirdparty/slf4j-reload4j-1.7.33.jar /opt/module/hbase/lib/client-facing-thirdparty/slf4j-reload4j-1.7.33.jar.bak
```

#### 4）HBase 远程发送到其他集群

```bash
[hadoop@hadoop100 module]$ xsync hbase/
```

#### 5）HBase 服务的启动

```bash
[hadoop@hadoop100 hbase]$ bin/hbase-daemon.sh start master
```

（2）群启：

### 3.3 Redis 部署（单机模式）

#### 集群规划

| 节点 | 角色 |
|------|------|
| hadoop100 | Redis Server（单实例，端口 6379） |

> 安装版本 6.0.8 for Linux（`redis-6.0.8.tar.gz`），不考虑在 Windows 环境下对 Redis 的支持。

#### 1）准备工作：安装最新版的 gcc 编译器

（1）安装 C 语言的编译环境：

```bash
sudo yum install centos-release-scl scl-utils-build
sudo yum install -y devtoolset-8-toolchain

# 注意：执行此命令会自动切换到 root 用户
sudo scl enable devtoolset-8 bash
```

（2）测试 gcc 版本：

```bash
gcc --version
```

#### 2）下载并解压

下载 `redis-6.0.8.tar.gz`，置于 `/opt/software` 目录下：

```bash
[hadoop@hadoop100 software]$ ll | grep redis
-rw-r--r--.  1 root    root      2247528 11月 22 08:46 redis-6.0.8.tar.gz
```

解压：

```bash
[hadoop@hadoop100 software]$ tar -zxvf redis-6.0.8.tar.gz -C ../module/
```

#### 3）编译并安装

（1）解压完成后进入目录 `redis-6.0.8`：

```bash
[hadoop@hadoop100 software]$ cd ../module/redis-6.0.8/
```

（2）在 `redis-6.0.8` 目录下执行 `make` 命令（只是编译好）：

```bash
[hadoop@hadoop100 redis-6.0.8]$ make
```

（3）如果 make 报错 `Jemalloc/jemalloc.h：没有那个文件`，解决方案：运行 `make distclean`：

```bash
[hadoop@hadoop100 redis-6.0.8]$ make distclean
```

（4）在 `redis-6.0.8` 目录下再次执行 `make` 命令（只是编译好），跳过 `make test`，继续执行 `make install`：

```bash
[hadoop@hadoop100 redis-6.0.8]$ make install
```

#### 4）安装目录说明

安装目录：`/usr/local/bin`，查看默认安装目录：

- `redis-benchmark`：性能测试工具，可以在自己本子运行，看看本子性能如何
- `redis-check-aof`：修复有问题的 AOF 文件
- `redis-check-dump`：修复有问题的 dump.rdb 文件
- `redis-sentinel`：Redis 集群使用
- `redis-server`：Redis 服务器启动命令
- `redis-cli`：客户端，操作入口

#### 5）配置文件修改

（1）切换到 hadoop 用户，拷贝 `redis.conf` 配置文件，置于 hadoop 家目录下：

> 若已按照文档中操作，则这一步可以省略。

```bash
[root@hadoop100 hadoop]# su hadoop
[hadoop@hadoop100 redis-6.0.8]$ cp /opt/module/redis-6.0.8/redis.conf ~/my_redis.conf
```

（2）修改redis.conf文件，注销 `bind` 配置项：

```
# bind 127.0.0.1
```

（3）修改redis.conf文件，修改 `protected-mode`：

```
protected-mode no
```

（4）修改my_redis.conf 文件，将 daemonize no 改为 daemonize yes

```
daemonize yes
```

#### 6）Redis 启动（后台启动，推荐）

```bash
[hadoop@hadoop100 ~]$ redis-server ./my_redis.conf
[hadoop@hadoop100 ~]$ ps -ef | grep redis
hadoop   26373      1  0 11:34 ?        00:00:00 redis-server 127.0.0.1:6379
hadoop   26384  26303  0 11:35 pts/0    00:00:00 grep --color=auto redis
```

#### 7）客户端访问

```bash
[hadoop@hadoop100 ~]$ redis-cli
127.0.0.1:6379>
```

多个端口可以：

```bash
[hadoop@hadoop100 ~]$ redis-cli -p 6379
127.0.0.1:6379>
```

测试验证：

```
127.0.0.1:6379> ping
PONG
127.0.0.1:6379>
```

#### 8）Redis 关闭

（1）单实例关闭：

```bash
[hadoop@hadoop100 ~]$ redis-cli shutdown
[hadoop@hadoop100 ~]$ ps -ef | grep redis
hadoop   26404  26303  0 11:37 pts/0    00:00:00 grep --color=auto redis
```

也可以进入终端后再关闭：

```bash
[hadoop@hadoop100 ~]$ redis-cli
127.0.0.1:6379> shutdown
not connected>
not connected>
[hadoop@hadoop100 ~]$
```

（2）多实例关闭，指定端口关闭：

```bash
[hadoop@hadoop100 ~]$ redis-server ./my_redis.conf
[hadoop@hadoop100 ~]$ redis-cli -p 6379 shutdown
[hadoop@hadoop100 ~]$ ps -ef | grep redis
hadoop   26432  26303  0 11:38 pts/0    00:00:00 grep --color=auto redis
[hadoop@hadoop100 ~]$
```

#### 9）Redis 单线程 + 多路 IO 复用技术

多线程 IO 默认不开启，需要在配置文件中配置：

```
io-threads-do-reads  yes
io-threads 4
```

#### 10）IDEA 连接 Redis 注意事项

（1）禁用 Linux 防火墙：

```bash
[hadoop@hadoop100 ~]$ sudo systemctl stop firewalld
[hadoop@hadoop100 ~]$ sudo systemctl disable firewalld
```

（2）确认 `my_redis.conf` 中已注销 `bind` 并将 `protected-mode` 改为 `no`（参见 5）配置文件修改）：

```
# bind 127.0.0.1
protected-mode no
```
