## 2. yum 源配置 + 基础软件包

> **每台都要执行**

### 2.1 更换 yum 镜像源

CentOS 默认源速度慢，替换为华为云（Base）和阿里云（EPEL）：

```bash
# 替换 Base 源 → 华为云
sudo curl -o /etc/yum.repos.d/CentOS-Base.repo https://repo.huaweicloud.com/repository/conf/CentOS-7-anon.repo

# 添加 EPEL 源 → 阿里云
sudo curl -o /etc/yum.repos.d/epel-7.repo http://mirrors.aliyun.com/repo/epel-7.repo

# 重建缓存
sudo yum clean all
sudo yum makecache

# 可选：更新系统（耗时较长，可跳过）
# sudo yum update -y
```

> **报错**：`curl: command not found` → 先执行 `sudo yum install -y curl`

### 2.2 安装必备软件包

```bash
sudo yum install -y epel-release net-tools vim rsync wget
```

| 软件包 | 用途 |
|--------|------|

| `vim` | 文本编辑器 |
| `rsync` | 集群分发脚本依赖 |

## 3. 静态 IP + 主机名 + hosts

### 3.1 配置静态 IP

> **每台都要执行**，IP 地址各不同！

```bash
sudo vim /etc/sysconfig/network-scripts/ifcfg-ens33
```

> 网卡名可能是 `ens33`、`eth0` 等，用 `ip addr` 查看你的实际网卡名。

修改以下内容：

```ini
# 将 dhcp 改为 static
BOOTPROTO="static"

# 末尾添加（hadoop100 为例，101/102 对应改 IP）
IPADDR=192.168.100.130
GATEWAY=192.168.100.2
DNS1=192.168.100.2
DNS2=8.8.8.8
```

三台机器各填自己的 IP：

| 机器 | IPADDR |
|------|--------|
| hadoop100 | 192.168.100.130 |
| hadoop101 | 192.168.100.131 |
| hadoop102 | 192.168.100.132 |

保存后重启网络：

```bash
sudo systemctl restart network
```

> **报错**：`Restarting network (via systemctl): Job for network.service failed`
> **原因**：ifcfg-ens33 配置有误（MAC 地址不匹配、格式错误）
> **解决**：检查文件内容，确认网卡名是否与 `ip addr` 输出的网卡名一致。如果用的是 VMware 克隆的虚拟机，需要额外修改 `HWADDR` 或 `UUID`。

### 3.2 修改主机名

> **每台都要执行**

```bash
# hadoop100 上执行
sudo hostnamectl set-hostname hadoop100

# hadoop101 上执行
sudo hostnamectl set-hostname hadoop101

# hadoop102 上执行
sudo hostnamectl set-hostname hadoop102
```

改完后执行 `bash` 或重新登录，终端才会显示新主机名。

### 3.3 配置 hosts 映射

> **每台都要执行**

```bash
sudo vim /etc/hosts
```

添加以下内容到文件末尾：

```
192.168.100.130  hadoop100
192.168.100.131  hadoop101
192.168.100.132  hadoop102
```

> **重要**：如果文件中有 `127.0.0.1 hadoopXXX` 这样的行，注释掉或删除。否则后续 Hadoop/Kafka 等组件绑定 IP 时会出问题（典型的 `UnknownHostException` 往往由此引起）。

### 3.4 验证网络

```bash
# 在 hadoop100 上执行
ping -c 2 hadoop101
ping -c 2 hadoop102
```

**预期**：三台两两互通，延迟 < 1ms。

## 4. 关闭防火墙 + SELinux

> **每台都要执行**。大数据集群内部通信频繁，防火墙和 SELinux 是 90% 组件通信故障的罪魁祸首。

```bash
# 关闭 firewalld
sudo systemctl stop firewalld
sudo systemctl disable firewalld.service

# 关闭 SELinux
sudo setenforce 0
sudo sed -i 's/^SELINUX=.*/SELINUX=disabled/' /etc/selinux/config
```

验证：

```bash
# 防火墙状态应为 inactive
sudo systemctl status firewalld

# SELinux 应为 Disabled
getenforce
```

## 5. 创建目录 + 配置 sudoers + PATH

### 5.1 创建工作目录

> **每台都要执行**

```bash
sudo mkdir -p /opt/software /opt/module
sudo chown -R hadoop:hadoop /opt/software /opt/module
```

### 5.2 给 hadoop 用户配置 sudo 权限

> **每台都要执行**。后续很多操作需要 sudo，不给权限会很痛苦。

```bash
sudo visudo
# 或者：sudo vim /etc/sudoers
```

在文件中找到 `%wheel  ALL=(ALL)  ALL`，在它下面添加一行：

```
hadoop  ALL=(ALL)  NOPASSWD: ALL
```

> `NOPASSWD` 表示 hadoop 用户执行 sudo 时无需输入密码，自动化脚本必需。

### 5.3 配置 PATH

> **每台都要执行**

```bash
mkdir -p /home/hadoop/bin
echo 'export PATH=$PATH:/home/hadoop/bin' >> ~/.bashrc
source ~/.bashrc
```

验证：`echo $PATH`，输出中应有 `/home/hadoop/bin`。

## 6. 集群分发脚本 xsync

> 只须在 **hadoop100** 上创建，注册到 PATH 后全局可用。

### 6.1 创建脚本

```bash
sudo vim /home/hadoop/bin/xsync
```

写入以下内容：

```bash
#!/bin/bash

# ====== 集群主机列表（统一维护，改这里即可）======
HOSTS="hadoop100 hadoop101 hadoop102"

# 判断参数个数
if [ $# -lt 1 ]; then
  echo "Usage: xsync <file1/dir1> [file2/dir2] ..."
  exit 1
fi

# 遍历集群所有机器
for host in $HOSTS; do
  echo "==================== $host ===================="

  for file in "$@"; do
    # 判断文件是否存在
    if [ -e "$file" ]; then
      pdir=$(cd -P "$(dirname "$file")" && pwd)
      fname=$(basename "$file")
      
      # 远程创建目录（sudo 提权）
      ssh $host "sudo mkdir -p $pdir"
      if [ $? -eq 0 ]; then
        # rsync 远程端同样 sudo 提权
        rsync -av --rsync-path="sudo rsync" "$pdir/$fname" "$host:$pdir"
      else
        echo "ERROR: Failed to create directory on $host"
      fi
    else
      echo "ERROR: $file does not exist!"
    fi
  done
done
```

### 6.2 赋予权限并分发

```bash
sudo chmod 777 /home/hadoop/bin/xsync

# 首次分发：用 scp 手动推到另外两台
scp -r /home/hadoop/bin hadoop101:/home/hadoop/
scp -r /home/hadoop/bin hadoop102:/home/hadoop/

# 验证：把脚本自己复刻一遍
xsync /home/hadoop/bin/xsync
```

> **报错：`rsync: command not found`** → `sudo yum install -y rsync`（第2步已装，一般不会遇到）
>
> **报错：`Permission denied`** → SSH 免密还没配，下一节解决。scp 和 rsync 暂时手动输密码。

## 8. SSH 免密登录配置

> **免密的正确姿势**：所有节点互信（每台都生成密钥 → 每台都发到所有节点）。为什么要全互信？因为后续很可能在任意一台节点上执行脚本访问其他节点。

### 8.1 在 hadoop100 上配置

```bash
# 1. 生成密钥对（三个回车，不设密码）
ssh-keygen -t rsa

# 2. 公钥拷贝到三台（包括自己）
ssh-copy-id hadoop100
ssh-copy-id hadoop101
ssh-copy-id hadoop102
```

执行 `ssh-copy-id` 时输入目标机器的 hadoop 用户密码。

### 8.2 在 hadoop101 上配置

```bash
ssh-keygen -t rsa
ssh-copy-id hadoop100
ssh-copy-id hadoop101
ssh-copy-id hadoop102
```

### 8.3 在 hadoop102 上配置

```bash
ssh-keygen -t rsa
ssh-copy-id hadoop100
ssh-copy-id hadoop101
ssh-copy-id hadoop102
```

### 8.4 验证

```bash
# 在 hadoop100 上执行
ssh hadoop101    # 免密码直接登录即成功
exit

ssh hadoop102    # 同理
exit
```

> **报错：`Permission denied (publickey)`**
>
> 原因：目标机器的 `~/.ssh/authorized_keys` 权限不正确
>
> 解决：**在目标机器上**执行：
> ```bash
> chmod 700 ~/.ssh
> chmod 600 ~/.ssh/authorized_keys
> ```
>
> **报错：`ssh-copy-id: command not found`**
>
> 原因：CentOS 最小化安装缺少该命令
>
> 解决：`sudo yum install -y openssh-clients`

## 9. 集群时钟同步

> **每台都要执行**。Hadoop/Kafka/HBase 等大量组件依赖时间戳，集群时间不一致会导致数据错乱、任务失败。

```bash
# 安装 ntpdate
sudo yum install -y ntpdate

# 首次同步（阿里云 NTP 服务器）
sudo ntpdate ntp.aliyun.com

# 设置定时任务：每天凌晨 2 点自动同步
sudo crontab -e
```

在 crontab 中加入以下行（第一行），保存退出：

```
0 2 * * * /usr/sbin/ntpdate ntp.aliyun.com
```

> 这只是教学环境方案。生产环境建议部署本地 NTP 服务器（如 hadoop100 部署 ntpd，其余节点指向它），避免所有节点同时请求外部服务器。
>
> **报错：`ntpdate: command not found`** → `sudo yum install -y ntpdate`
>
> **报错：`crontab: command not found`** → `sudo yum install -y crontabs`

## 10. JDK 安装

### 10.1 卸载已有 JDK

```bash
# SSH免密已配好，用 xcall 三台批量操作
xcall "sudo rpm -qa | grep -i java | xargs -r sudo rpm -e --nodeps 2>/dev/null"
```

> 参数含义：
> - `rpm -qa` — 查询所有已安装软件包
> - `grep -i java` — 不区分大小写过滤
> - `xargs -r` — 逐条卸载（`-r` 表示无匹配项时不执行，避免报错）
> - `rpm -e --nodeps` — 强制卸载，忽略依赖

### 10.2 下载并安装 JDK

在 **hadoop100** 上操作：

#### Oracle JDK（课程文档推荐，稳定）

```bash
# 将 jdk-8u212-linux-x64.tar.gz 上传到 /opt/software/
# 用 XShell 的 rz、WinSCP、scp 等工具

# 解压
tar -zxvf /opt/software/jdk-8u212-linux-x64.tar.gz -C /opt/module/

# 重命名
mv /opt/module/jdk1.8.0_212 /opt/module/jdk-1.8.0
```

### 10.3 配置环境变量

```bash
sudo vim /etc/profile.d/my_env.sh
```

写入：

```bash
# JAVA_HOME
export JAVA_HOME=/opt/module/jdk-1.8.0
export PATH=$JAVA_HOME/bin:$PATH
export CLASSPATH=.:$JAVA_HOME/lib/dt.jar:$JAVA_HOME/lib/tools.jar
```

> **为什么放在 `/etc/profile.d/my_env.sh`？** login shell 和 non-login shell 都会加载该目录下所有 `.sh`，全局可用。后续所有组件（Hadoop/Hive/Kafka 等）的环境变量都追加到这个文件。

### 10.4 验证

```bash
source /etc/profile
java -version
```

预期输出类似：

```
openjdk version "1.8.0_492"
OpenJDK Runtime Environment (build 1.8.0_492-b09)
OpenJDK 64-Bit Server VM (build 25.492-b09, mixed mode)
```

### 10.5 分发 JDK + 环境变量

```bash
# 分发 jdk
xsync /opt/module/jdk-1.8.0

# 分发环境变量
xsync /etc/profile.d/my_env.sh

# 三台机器刷新环境变量
xcall "source /etc/profile"
```

### 10.6 确认三台 JDK 都可用

```bash
xcall java -version
```

三台都应该正常输出版本信息。

## 12. 高频报错速查

| 报错 | 原因 | 解决 |
|------|------|------|
| `network.service failed` | ifcfg 配置错误 | 检查网卡名是否匹配 `ip addr`，检查 MAC 地址 |
| `UnknownHostException` | hosts 中 127.0.0.1 指向主机名 | 注释掉 `/etc/hosts` 中 `127.0.0.1 hadoopXXX` |
| 组件绑定端口失败 | 防火墙未关闭 | `sudo systemctl stop firewalld` |
| `rsync: command not found` | 未安装 | `sudo yum install -y rsync` |
| `Permission denied (publickey)` | SSH authorized_keys 权限不对 | `chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys` |
| `ssh: port 22: Connection refused` | sshd 未启动 | `sudo systemctl start sshd && sudo systemctl enable sshd` |
| `bash: xsync: command not found` | bin 不在 PATH | `source ~/.bashrc` 后重试，或重新登录 |
| `java: command not found` | 环境变量未生效 | `source /etc/profile` 后重试 |
| `sudo: hadoop 不在 sudoers` | 未配置 sudo 权限 | 参考第 5.2 节配置 |
| `crontab: command not found` | 未安装 | `sudo yum install -y crontabs` |
